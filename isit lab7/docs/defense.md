# Ответы на контрольные вопросы

1. **Ресурс REST и страница сайта.** Ресурс — сущность с адресом, например заявка `/api/tickets/3`. API возвращает её данные в JSON, а страница `/tickets/3` — готовый HTML для человека.
2. **Существительные в URL.** Адрес обозначает ресурс, действие задаёт HTTP-метод. Поэтому используется POST `/api/tickets`, а не `/createTicket`. Коллекции названы во множественном числе; staff — собирательное имя сотрудников.
3. **CRUD.** Create — POST; Read — GET списка и объекта; Update — PUT/PATCH; Delete — DELETE.
4. **PUT и PATCH.** Обычно PUT заменяет ресурс целиком, PATCH меняет часть. В этой учебной работе оба направлены в `update()` и объединяют присланные поля с прежними через `array_replace`.
5. **201 и Location.** 201 сообщает о создании нового ресурса, Location указывает его адрес. Клиент может выполнить GET по этому адресу.
6. **204.** Удаление успешно, передавать данные больше не нужно. Тело должно отсутствовать, даже пустой JSON-объект отправлять нельзя.
7. **400 и 422.** POST с телом `абс` — 400, потому что это не JSON. Объект с коротким названием — 422: JSON корректен, поля не проходят проверку.
8. **405 и Allow.** Путь существует, но не поддерживает выбранный метод. DELETE `/api/categories` получает 405 и `Allow: GET, POST`.
9. **409.** Запрос конфликтует с текущим состоянием данных: нельзя удалить категорию, пока на неё ссылаются заявки. Сначала нужно удалить заявки или перенести их в другую категорию.
10. **Серверная проверка.** Клиентскую проверку можно обойти через curl или собственную программу. Сервер проверяет типы и значения, существование категории; `clean()` удаляет неизвестные поля и попытки изменить ID.
11. **Документация.** Клиенту нужны метод, URL, назначение, параметры пути/query/тела, типы и обязательность, примеры запросов и ответов, HTTP-коды и ошибки. Все 19 endpoints описаны в `api.md`.
12. **Перенос.** Переименованы API-контроллеры, модели, JSON-файлы и маршруты; изменены `clean`/`validate`, связь `project_id` → `category_id`, `byProject` → `byCategory`. Срок задачи заменён описанием обращения, участники — сотрудниками поддержки. HTML-сайт также перенесён. Общие Router, JSON-функции и JsonRepository при переносе не менялись.
