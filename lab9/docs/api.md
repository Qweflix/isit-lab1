# REST API системы учёта заявок

## 1. Общие правила

Базовый адрес: `http://127.0.0.1:8000/api`. Запросы с телом используют `Content-Type: application/json`. Клиент и сервер работают на одном адресе; CORS не требуется. Все маршруты API, кроме `POST /auth/login`, требуют `Authorization: Bearer <token>`.

Список — массив объектов, одна запись — объект. Числовые ID приходят числами, необязательные поля — `null`, даты — строки. Успешное удаление возвращает **204 без тела**. Создание — **201** и `Location`. PUT и PATCH, как в ЛР7, изменяют только присланные поля; ID изменить нельзя. Неизвестные поля не сохраняются.

Ошибка имеет единый формат:

```json
{"error":"Ошибка проверки данных","errors":{"title":"Длина от 3 до 200 символов."}}
```

При отсутствии ошибок отдельных полей `errors` равен `{}`. В интерфейсе 422 отображается у полей формы, 401 возвращает на вход, 403 показывает недостаток прав. Ошибка сети отличается от HTTP-ответа; 503 означает недоступность БД, 500 — внутреннюю ошибку.

## 2. Вход и токены

| Метод | Адрес | Вход | Ответ |
| --- | --- | --- | --- |
| POST | `/auth/login` | email, password — строки | 200: token, expires_at, user; 400/401/422/503 |
| GET | `/auth/me` | Bearer-токен | 200: id, name, email, role; 401/503 |
| POST | `/auth/logout` | Bearer-токен | 204: токен отозван; 401/503 |

Пример тела входа (пароль задаётся при локальном заполнении БД):

```json
{"email":"manager@example.test","password":"<локальный учебный пароль>"}
```

Ответ:

```json
{"token":"<64 hex-символа>","expires_at":"<ISO 8601>","user":{"id":1,"name":"Алексей Смирнов","email":"manager@example.test","role":"manager"}}
```

Пароли сохраняются через `password_hash`, проверяются через `password_verify`. Токен генерируется `random_bytes(32)`, действует **7200 секунд**, в `auth_tokens` хранится только SHA-256. Пользователь хранится отдельно от справочника сотрудников; `users.staff_id` связывает его со `staff`. Должность `staff.role` сохранена из ЛР8 и не используется для проверки прав.

На клиенте хранится только токен `localStorage.authToken`. При загрузке страницы роль повторно запрашивается с сервера; изменение роли в браузере не даёт прав на сервере. При выходе текущий токен удаляется из БД; при ошибке сети выход можно повторить. Истечение проверяется по `expires_at > CURRENT_TIMESTAMP` при каждом запросе.

## 3. Роли

| Действие | manager — руководитель | operator — оператор |
| --- | --- | --- |
| Читать заявки, категории, сотрудников | Да | Да |
| Создавать и изменять заявки | Да | Да |
| Удалять заявки | Да | 403 |
| Создавать, изменять, удалять категории и сотрудников | Да | 403 |

В интерфейсе оператора нет кнопки удаления. Проверка `Auth::requireRole` действует и при прямом запросе в обход интерфейса.

## 4. Заявки

| Метод | Адрес | Результат | Роль |
| --- | --- | --- | --- |
| GET | `/tickets` | 200: массив заявок | Обе |
| GET | `/tickets/{id}` | 200: заявка | Обе |
| POST | `/tickets` | 201: созданная заявка | Обе |
| PUT | `/tickets/{id}` | 200: изменённая заявка | Обе |
| PATCH | `/tickets/{id}` | 200: изменённая заявка | Обе |
| DELETE | `/tickets/{id}` | 204 | manager |

Поля записи: `id`, `category_id`, `assignee_id`, `title`, `description`, `status`, `priority`, `due_date`, `created_at`.

- `title`: строка от 3 до 200 символов; `description`: непустая строка.
- `category_id`: обязательный числовой ID существующей категории.
- `assignee_id`: числовой ID сотрудника либо `null`; по умолчанию `null`.
- `status`: `new`, `in_progress`, `done`; по умолчанию `new`.
- `priority`: `low`, `medium`, `high`, `critical`; по умолчанию `medium`.
- `due_date`: действительная дата `YYYY-MM-DD` либо `null`; пустая строка недопустима.
- `id`, `created_at` назначаются БД.

Пример создания:

```json
{"title":"Не работает принтер","description":"Документы остаются в очереди.","category_id":1,"assignee_id":1,"priority":"high","status":"new","due_date":null}
```

GET `/tickets` принимает совместимые параметры: `q` — подстрока темы без учёта регистра (включая кириллицу), `status`, `category_id`, `sort` — `id`/`title`/`due_date`/`created_at`, `order` — `asc`/`desc`. По умолчанию `id asc`; NULL-сроки последние, ID служит дополнительным порядком. Фильтры передаются параметрами PDO; имя столбца сортировки выбирается из белого списка. Неверные параметры — 422, пустой результат — `[]` и 200.

Примеры: `/tickets?q=компьютер`, `/tickets?status=done&category_id=2`, `/tickets?sort=due_date&order=asc`.

## 5. Категории

| Метод | Адрес | Результат | Роль |
| --- | --- | --- | --- |
| GET | `/categories` | 200: массив | Обе |
| GET | `/categories/{id}` | 200: объект | Обе |
| POST | `/categories` | 201: объект | manager |
| PUT | `/categories/{id}` | 200: объект | manager |
| PATCH | `/categories/{id}` | 200: объект | manager |
| DELETE | `/categories/{id}` | 204 | manager |
| GET | `/categories/{id}/tickets` | 200: массив связанных заявок | Обе |

Поля: `id`, `title` (3–150 символов, уникально), `description` (строка или null), `owner_id` (обязательный числовой ID сотрудника), `created_at`.

Пример POST: `{"title":"Телефония","description":"Связь и телефоны","owner_id":1}`. Удаление категории с заявками — 409. Несуществующая категория в связанном маршруте — 404.

## 6. Сотрудники

| Метод | Адрес | Результат | Роль |
| --- | --- | --- | --- |
| GET | `/staff` | 200: массив | Обе |
| GET | `/staff/{id}` | 200: объект | Обе |
| POST | `/staff` | 201: объект | manager |
| PUT | `/staff/{id}` | 200: объект | manager |
| PATCH | `/staff/{id}` | 200: объект | manager |
| DELETE | `/staff/{id}` | 204 | manager |

Поля: `id`, `name` (3–100 символов), `email` (корректный, уникальный, до 255 символов), `role` (должность, 1–100 символов, по умолчанию «Инженер поддержки»), `created_at`. Пример POST: `{"name":"Иван Петров","email":"ivan@example.test","role":"Оператор поддержки"}`.

Ограничения ЛР8 сохранены: удаление владельца категории или автора комментария запрещено (409); исполнитель удалённого сотрудника становится NULL, профиль удаляется каскадно, связь учётной записи становится NULL.

## 7. Коды и защита

| Код | Значение |
| --- | --- |
| 400 | Некорректный JSON или тело не объект |
| 401 | Отсутствующий, недействительный, истёкший или отозванный токен; неверный вход |
| 403 | Не хватает прав |
| 404 | Нет маршрута или записи |
| 405 | Метод не разрешён, есть Allow |
| 409 | Нарушение UNIQUE (23505) или внешнего ключа (23503) |
| 422 | Ошибки полей, фильтров или сортировки |
| 500 | Внутренняя ошибка без технических деталей |
| 503 | Нет подключения к БД |

Дополнительная возможность методички — преобразование SQLSTATE 23503/23505 в 409. Подробности SQL и пароли клиенту не отправляются. Значения SQL передаются через подготовленные запросы. Публиковать учебный сервер в интернет без HTTPS, ограничения входов и дополнительной защиты не следует.
