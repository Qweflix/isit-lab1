API-тест содержит больше требуемых 57 проверок. Дополнительные проверки домашней доработки: совместные фильтры категории и статуса, обратная сортировка, неверный календарный день, неизменяемость ID, повторное использование отозванного токена. ## 3. Безопасность

| Проверка | Фактический результат |
| --- | --- |
| Защищённые API без токена | tickets/categories/staff/me и неизвестный API возвращают 401 |
| Поддельный и отозванный токен | 401; истёкший токен в браузере очищается, показан вход |
| Обход скрытой кнопки | Прямой DELETE оператором — 403, запись сохранена |
| Пароль не передаётся клиенту | В ответах login/me и ресурсах нет password_hash |
| Хранение пароля | В БД хеш; password_verify с локальным паролем возвращает true |
| Хранение токена | В БД найден SHA-256 выданного токена; самого токена нет |
| SQL-инъекция при входе | Адрес `' OR 1=1 --` не даёт вход, 401 |
| SQL-инъекция в поиске | Поиск `' OR 1=1 --` возвращает пустой массив; таблица сохранена |
| Инъекция в sort | Недопустимое имя столбца — 422 |
| XSS в теме заявки | Строка `<img src=x onerror="window.xss=true">` показана текстом; DOM img не создан, код не выполнен |

[Ответ прямого DELETE](403-response.txt), [curl без авторизации](curl-auth.txt), [метаданные базы без значений хешей](database.txt).

## 4. Найденные ошибки

Первый браузерный прогон прошёл A01–A18, но остановился на A19: при отключении БД PDO вернул код 7, который ошибочно попал в общий ответ 500. Ошибка подключения теперь отдельно оборачивается в DatabaseUnavailable и превращается в безопасный 503. Также исправлена команда восстановления контейнера: данная версия Compose не поддерживает `start --wait`, используется `up -d --wait db`. После исправлений повторно прошли все 24 сценария и 87 API-проверок.

Во время подготовки обычные Docker-образы заполнили системный диск. Временные образы удалены; воспроизводимая конфигурация использует компактный Alpine и только PHP/PDO/mbstring. При сборке в облаке доверенный сертификат прокси передавался BuildKit secret, в образ он не записан.

## 5. Повторный запуск

Сначала выполнить инструкцию README и сохранить DEMO_PASSWORD в окружении текущего терминала. Из `lab9/src`:

```bash
docker compose -p lab9 exec -T -e DEMO_PASSWORD web php84 tests/api-tests.php
docker compose -p lab9 exec -T -e DEMO_PASSWORD web php84 tests/storage-tests.php
docker compose -p lab9 exec -T web sh -c 'find app bin config public routes tests -name "*.php" -exec php84 -l {} \;'
```

Для браузера нужны Python 3 и Playwright (это инструменты тестирования, приложению не требуются):

```bash
python -m pip install playwright
python -m playwright install chromium
COMPOSE_PROJECT_NAME=lab9 python tests/browser-tests.py
```

Браузерный тест останавливает контейнеры проекта lab9; запускать только на своей учебной копии. `APP_URL` и `COMPOSE_PROJECT_NAME` переопределяются переменными. API-тест рассчитан на шесть начальных заявок, его временные записи удаляются; повторный запуск проверен. Сброс БД выполняется отдельно явной командой `bin/reset-db.php --confirm` и удаляет данные только выбранной в конфигурации БД.
